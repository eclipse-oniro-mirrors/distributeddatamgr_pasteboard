# 设计文档：PasteId 传参优化 — 从 string PasteId 改为 uint32_t PasteSeqId

## Overview

将剪贴板模块中 Client→Service 的 GetPasteData 传参从 `String` 类型改为 `unsigned int` 类型（PasteSeqId）。Client 端仅传递递增序列号 seq，Service 端收到后根据 `IPCSkeleton::GetCallingPid()` 和 seq 拼接完整 string PasteId 并设置到 PasteData。

PasteStart/PasteComplete 无需修改 — 它们仍传递 string pasteId（从 PasteData.GetPasteId() 获取，该值已由 Service 端设置）。NAPI/Taihe 无需修改。PasteSeqId 仅作为 GetPasteData 的 IDL IPC 参数传递，不在 PasteData 中新增成员变量。

## Architecture

修改范围大幅缩小，仅涉及 GetPasteData 链路：

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│  NAPI/Taihe  │     │  IDL (IPC)   │     │  Service 端      │
│  无修改      │     │  仅GetPaste  │     │  GetPasteData    │
│              │     │  Data 1处    │     │  拼接pasteId     │
└─────────────┘     └──────────────┘     └─────────────────┘
                           ↓                      ↓
┌─────────────────────────────────────────────────────────────┐
│                   PasteData (数据模型)                        │
│  保留: std::string pasteId_ (Service端赋值)                  │
│  删除: IsValidPasteId()                                     │
│  保留: CreatePasteId() → 新增三参数版本                      │
│  不新增: pasteSeqId_ 成员                                    │
└─────────────────────────────────────────────────────────────┘

PasteStart/PasteComplete 链路（无修改）：
Client string pasteId → IPC String → Service string pasteId → P2P/timer/radar
```

## Components and Interfaces

### 1. IDL 接口变更（IPasteboardService.idl）

仅 1 处变更：

| ipc code | 原接口 | 新接口 |
|----------|--------|--------|
| 200 | `GetPasteData([in] String pasteId)` | `GetPasteData([in] unsigned int pasteSeqId)` |

PasteStart (ipc code 202) 和 PasteComplete (ipc code 203) **不变**，仍为 `[in] String pasteId`。

### 2. PasteData 类变更（paste_data.h / paste_data.cpp）

**删除：**
- `static bool IsValidPasteId(const std::string &pasteId);` 声明和实现
- `constexpr int32_t SUB_PASTEID_NUM = 3;` 和 `constexpr int32_t PASTEID_MAX_SIZE = 1024;` 常量（仅 IsValidPasteId 使用）
- IsValidPasteId() 实现体（paste_data.cpp 875-898行）

**新增：**
- `static std::string CreatePasteId(const std::string &name, uint32_t sequence, pid_t pid);` — 三参数版本，Service 端传入 callingPid
- 原 `CreatePasteId(name, sequence)` 两参数版本保留（内部仍用 getpid()），但不再被 Client 端调用

**保留不变：**
- `void SetPasteId(const std::string &pasteId);` / `std::string GetPasteId() const;`
- `std::string pasteId_;` — Service 端赋值，NAPI/Taihe 仍通过 GetPasteId() 获取
- TLV `TAG_PASTE_ID` 序列化不变
- 拷贝构造/赋值运算符不变

### 3. PasteboardClient 变更（pasteboard_client.h / pasteboard_client.cpp）

**PasteDataFromServiceInfo 结构体变更：**
- `std::string currentId;` → `uint32_t currentSeqId;`
- `std::string currentPid;` 保留

**方法签名 — 不变更：**
- `PasteStart(const std::string &pasteId);` — 保持不变
- `PasteComplete(const std::string &deviceId, const std::string &pasteId);` — 保持不变

**GetPasteData() 调用逻辑变更：**
- 原：`std::string currentId = PasteData::CreatePasteId("GetPasteData", getSequenceId_++);`
- 新：`uint32_t seqId = getSequenceId_++;`
- IPC：`proxyService->GetPasteData(fd, rawDataSize, recvTLV, seqId, syncTime, realErrCode)`
- Radar CONCURRENT_ID：`std::to_string(seqId)` 代替 `currentId`

**ProgressRadarReport() 变更：**
- 原：`pasteDataFromServiceInfo.currentId = PasteData::CreatePasteId("GetDataWithProgress", getSequenceId_++);`
  `pasteData.SetPasteId(pasteDataFromServiceInfo.currentId);`
- 新：`pasteDataFromServiceInfo.currentSeqId = getSequenceId_++;`
  不再调用 `pasteData.SetPasteId()`（Service 端会在返回的 PasteData 中设置 pasteId）
- Radar CONCURRENT_ID：`std::to_string(pasteDataFromServiceInfo.currentSeqId)` 代替 `pasteDataFromServiceInfo.currentId`

**GetPasteDataFromService() 变更：**
- 原：`proxyService->GetPasteData(fd, rawDataSize, recvTLV, pasteId, ...)` 其中 `pasteId` 是 string
- 新：`proxyService->GetPasteData(fd, rawDataSize, recvTLV, pasteDataFromServiceInfo.currentSeqId, ...)` 传 uint32_t
- Radar 中所有使用 `pasteDataFromServiceInfo.currentId` 的地方改为 `std::to_string(pasteDataFromServiceInfo.currentSeqId)`

**GetDataReport() 变更：**
- 参数 `const std::string &currentId` 改为 `uint32_t currentSeqId`
- 内部 radar 上报中 currentId 改为 `std::to_string(currentSeqId)`

**PasteStart/PasteComplete — 不变更：**
- 仍传递 string pasteId（从 PasteData.GetPasteId() 获取）
- IPC 调用不变（IDL 仍是 String）

### 4. PasteboardService 变更（pasteboard_service.h / pasteboard_service.cpp）

**仅 GetPasteData 链路变更：**

- `GetPasteData(..., const std::string &pasteId, ...)` → `uint32_t pasteSeqId`
- `GetPasteDataInner(..., const std::string &pasteId, ...)` → `uint32_t pasteSeqId`
- `CheckAndGrantRemoteUri(..., const std::string &pasteId, ...)` → `uint32_t pasteSeqId`

**GetPasteData() 核心逻辑变更：**
- 删除 `IsValidPasteId(pasteId)` 校验
- 新增拼接：`std::string pasteId = PasteData::CreatePasteId("GetPasteData", pasteSeqId, IPCSkeleton::GetCallingPid());`
- `data.SetPasteId(pasteId);` 保留（Service 端设置完整 pasteId 到 PasteData）

**PasteStart/PasteComplete — 不变更：**
- 仍接收 `const std::string &pasteId`
- 内部逻辑（timer、P2P map、radar）不变

**EstablishP2PLink/CheckAndReuseP2PLink/EstablishP2PLinkTask — 不变更：**
- 这些函数的 pasteId 参数仍为 string，由 Service 内部拼接后传入

**注意：** Service 内部调用 `EstablishP2PLink(networkId, pasteId)` / `CheckAndGrantRemoteUri(data, appInfo, pasteId, ...)` 时，pasteId 已在入口处由 Service 拼接，所以内部传递仍用 string。

### 5. NAPI/Taihe — 不变更

- PasteStart/PasteComplete 仍从 PasteData.GetPasteId() 获取 string pasteId
- 传递给 PasteboardClient::PasteStart(string) / PasteComplete(deviceId, string)
- 完全不受影响

### 6. Error Handler 变更

`error_handler.cpp` 中 `"Invalid pasteId parameter"` → `"Invalid pasteSeqId parameter"`

## Data Models

### PasteId 拼接

```
PasteId = "{name}_{callingPid}_{pasteSeqId}"
```

Service 端使用 `CreatePasteId(name, pasteSeqId, IPCSkeleton::GetCallingPid())` 拼接。

### PasteDataFromServiceInfo 变更

```cpp
struct PasteDataFromServiceInfo {
    pid_t pid;
    std::string currentPid;    // 保留，radar需要
    uint32_t currentSeqId;     // 原为 std::string currentId
};
```

### PasteData 不新增 TLV tag

pasteSeqId 不存入 PasteData，TLV 序列化仅保留原有 TAG_PASTE_ID（string pasteId_）不变。

## Error Handling

### 删除 IsValidPasteId 校验

原逻辑在 Service GetPasteData 入口校验 pasteId 格式。修改后 Service 自行拼接 pasteId，无需校验外部传入的 string。

### PasteStart/PasteComplete 不变

这两个方法仍接收 string pasteId，其内部逻辑（CancelTimer、P2P map）不变，无需额外处理。
