# 需求文档：PasteId 传参优化 — 从 string PasteId 改为 uint32_t PasteSeqId

## 问题描述

当前剪贴板模块中，Client 端通过 `PasteData::CreatePasteId(name, seq)` 生成包含 `pid` 和 `seq` 的字符串标识（格式 `{name}_{pid}_{sequence}`），并以 `String` 类型通过 IDL IPC 传递给 Service 端。Service 端通过 `IsValidPasteId()` 校验传入的 PasteId 格式及 PID 匹配性。

然而，PID 信息可以由 Service 端通过 `IPCSkeleton::GetCallingPid()` 自行获取，Client 端无需也不应传递 PID。Client 端仅需传入递增序列号 `seq` 即可，Service 端根据 `callingPid` 和 `seq` 拼接完整 PasteId。

## 用户故事

- **Client 端开发者**: 我只需关心每次粘贴操作的序列号，不需要知道自己的 PID，也不需要构造复杂的字符串标识
- **Service 端开发者**: 我通过 IPC 框架已能获取调用方 PID，无需依赖 Client 端传入的 PID 字段，直接根据 callingPid + seq 拼接即可
- **IDL 接口维护者**: 传参类型从 `String` 改为 `uint32_t`，接口更简洁，IPC 开销更小

## 功能需求列表

### FR-1: IDL 接口参数类型变更
- IPasteboardService.idl 中 4 处 `[in] String pasteId` 参数改为 `[in] unsigned int pasteSeqId`
- 涉及 ipc code 200 (GetPasteData)、202 (PasteStart)、203 (PasteComplete)

### FR-2: Client 端修改
- PasteboardClient 不再调用 `PasteData::CreatePasteId()`，改为仅使用 `getSequenceId_++` 生成 `uint32_t PasteSeqId`
- Client 端 IPC 调用传递 `uint32_t pasteSeqId` 而非 `std::string pasteId`
- PasteData 类新增 `uint32_t pasteSeqId_` 成员及对应 getter/setter
- PasteData 类保留 `std::string pasteId_` 成员，但由 Service 端设置（Client 端不再设置）

### FR-3: Service 端修改
- Service 端方法签名中 `const std::string &pasteId` 参数改为 `uint32_t pasteSeqId`
- Service 端在收到 `pasteSeqId` 后，调用 `PasteData::CreatePasteId()` 根据 callingPid + pasteSeqId 拼接完整 string PasteId
- 删除 `PasteData::IsValidPasteId()` 函数（Service 端自行拼接，无需校验外部传入的 string）
- Service 端所有使用 pasteId 的内部逻辑（P2P map、timer、radar）不变，继续使用拼接后的 string pasteId

### FR-4: TLV 序列化适配
- PasteData 的 TLV 序列化/反序列化需适配新增的 `pasteSeqId_` 字段
- `pasteId_` 字段仍保留 TLV 序列化（Service 端设置后需要跨进程传输）

### FR-5: DFX/Radar 适配
- RadarPasteInfo 中 `std::string pasteId` 字段保持不变（Service 端拼接后仍为 string）
- Radar 上报逻辑无需变更

## 约束条件

- Client 端不可访问 PID 信息，仅传递 seq
- Service 端必须使用 `IPCSkeleton::GetCallingPid()` 获取调用方 PID
- IDL 生成代码（stub/proxy）由编译工具自动生成，无需手动修改
- PasteData::CreatePasteId 保留但改为 Service 端专用
- PasteData::IsValidPasteId 删除
- 不改变 P2P map、timer、radar 等使用 string pasteId 的内部逻辑

## 成功标准

1. IDL 文件中 pasteId 相关参数类型从 String 改为 unsigned int
2. Client 端仅传递 uint32_t PasteSeqId，不传递 PID
3. Service 端根据 callingPid + PasteSeqId 拼接 string PasteId
4. IsValidPasteId 函数被删除
5. CreatePasteId 函数保留，由 Service 端调用
6. 所有编译通过，既有测试适配更新
7. Fuzz 测试适配更新
